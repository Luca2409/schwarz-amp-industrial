# AMP – Website

Bilingual (German/English) company website for AMP Prüftechnik, built with [Astro](https://docs.astro.build/) as a static site and deployed to GitHub Pages.

- **Live:** https://luca2409.github.io/schwarz-amp-industrial/
- **Stack:** Astro 6, TypeScript, Markdown content collections, `astro:assets` image optimization, `@astrojs/sitemap`, Inter via Fontsource (self-hosted)

## Getting started

Requires Node.js 22 (same as CI).

```bash
npm install
npm run dev
```

The dev server runs at http://localhost:4321/schwarz-amp-industrial/ and redirects to `/de/` or `/en/` based on your browser language.

| Script | Purpose |
| --- | --- |
| `npm run dev` | Dev server with hot reload |
| `npm run check` | Type-check `.astro` and `.ts` files, incl. missing translation keys |
| `npm run build` | Production build into `dist/` (pages, optimized images, sitemap) |
| `npm run preview` | Serve the production build locally |
| `npm run test:e2e` | Playwright end-to-end tests (needs Google Chrome installed) |

Run `npm run check`, `npm run build` and `npm run test:e2e` before pushing. The build prints `[i18n]` warnings for content that's missing in a language and `[site-checks]` warnings for unfilled `[placeholders]`.

> **Placeholders block deployment:** in CI, the build fails while `[placeholders]` remain in `src/site.ts`, `src/i18n/ui.ts` or the legal pages. All checks: [docs/quality-checks.md](docs/quality-checks.md).

> After changing `src/content.config.ts`, restart the dev server. Its content cache doesn't always recover from schema changes.

## Project structure

```
.github/workflows/deploy.yml   Build and deploy to GitHub Pages
astro.config.mjs               i18n, sitemap, integrations
deploy.config.mjs              Domain (site) and base path, shared with the e2e tests
docs/                          Documentation (index: docs/README.md)
playwright.config.ts           E2E test setup
public/                        Files served as-is (favicon, logo)
src/
  assets/images/               Images processed by astro:assets
  components/                  UI components (Header, Hero, Footer, …)
  content/                     Markdown content, one folder per language
    pages/<lang>/home.md         Home page texts
    competencies/<lang>/*.md     Competency pages
    legal/<lang>/*.md            Impressum, privacy policy
  content.config.ts            Content collection schemas
  i18n/                        UI translations, localized routes, URL helpers, sitemap serializer
  integrations/                Build checks (placeholders, static route files)
  layouts/BaseLayout.astro     HTML shell with all SEO tags
  lib/                         Content helpers, structured data, last-modified dates
  pages/                       Routes (see URL overview below)
  site.ts                      Company data, related companies, address, contact person, form service, map URL
  styles/global.css            All styles
tests/e2e/                     Playwright tests (contact form, map, language switching, root redirect)
```

Imports use the alias `@/` for `src/` (configured in `tsconfig.json`), e.g. `import { site } from '@/site'`.

## Editing content

Content is Markdown with YAML frontmatter, one file per language. The schemas in `src/content.config.ts` validate every field; invalid or missing fields fail the build with a clear error.

### Home page

`src/content/pages/de/home.md` and `src/content/pages/en/home.md` hold the texts of all home page sections:

| Frontmatter prefix | Section | Component |
| --- | --- | --- |
| `title`, `description` | `<title>` and meta description | `BaseLayout` |
| `hero*`, `primaryCta*`, `secondaryCta*` | Hero | `Hero.astro` |
| `showcase*` | Image below the hero | `ImageShowcase.astro` |
| `about*` + Markdown body | Know-how | `AboutSection.astro` |
| `competencies*` | Competencies list | `CompetenciesSection.astro` |
| `quality*` | Quality | `QualitySection.astro` |
| `contact*` | Contact banner (links to the contact page) | `ContactBanner.astro` |

### Competencies

Each competency is one file per language in `src/content/competencies/<lang>/`. The file name is the URL slug, and both language versions share a `translationKey`. Each file automatically creates a row in the home page list, a detail page, an entry in the "related" list of the other competency pages, and sitemap entries.

```yaml
---
translationKey: "dimensional-metrology"   # same in all languages
number: "02"
title: "Vermessung"
teaser: "Laserbasierte Präzisionsmessung für industrielle Anwendungen."
order: 2
seoTitle: "Lohnvermessung mit FARO Laser Tracker & FaroArm | AMP"   # ≤ 60 characters
seoDescription: "Präzise 3D-Vermessung von …"                            # 120–160 characters
# ogImage: "../../../assets/images/…"     # optional social preview image
---

Markdown body …
```

Step-by-step guide: [Add a competency](docs/i18n-seo.md#add-a-competency).

### Legal pages

Impressum and privacy policy live in `src/content/legal/<lang>/` and are linked in the footer. **They're templates:** fill in every `[placeholder]` and have them legally reviewed before going live.

### UI texts

Navigation, buttons, footer and other fixed texts are translation keys in `src/i18n/ui.ts`, not in the components. See [UI translations](docs/i18n-seo.md#ui-translations).

### Company data

Email, phone, company name, logo, related companies (footer links), address, contact person, form service and map URL are defined once in `src/site.ts` and used by the footer, contact page and structured data. The legal Markdown files repeat email and phone and must be updated by hand.

### Certificates

Certificates and memberships are listed in `src/lib/certificates.ts` (title and description per language, issuer, `validUntil`, PDF per language) and rendered by `CertificatesPage.astro`. The PDFs live in `public/files/certificates/`; a missing English PDF falls back to the German one ("German only"). The validity date isn't shown on the page, but the build warns about expired certificates (`[certificates] … expired`). The page is linked in the main navigation, the footer and the quality section on the home page.

### Contact page

Configured in `src/site.ts` (address, contact person, form service) and `src/i18n/ui.ts` (`contact.*` texts). Setup, form providers and legal notes: [docs/contact-page.md](docs/contact-page.md).

### Images

Put content images into `src/assets/images/` and reference them in frontmatter with a path relative to the Markdown file:

```yaml
heroImage: "../../../assets/images/hero-image.jpg"
```

Astro converts them to WebP in several sizes at build time. Only files that need a fixed URL (favicon, logo for structured data) belong in `public/`.

## Deployment

`.github/workflows/deploy.yml` builds and deploys the site to GitHub Pages on every push to `main` (or manually via *Run workflow*):

1. Checkout with full git history (`fetch-depth: 0`, needed for the sitemap's `lastmod` dates)
2. Node 22, `npm ci`, `npm run build` (fails while `[placeholders]` are left)
3. `npm run test:e2e` against a separate build in `dist-e2e/`; on failure, traces are uploaded as artifact `playwright-traces`
4. Upload `dist/` and deploy to GitHub Pages

The repository's Pages setting must use **GitHub Actions** as source.

`site` and `base` in `deploy.config.mjs` match the GitHub Pages project URL. Both `astro.config.mjs` and `playwright.config.ts` read them from there. When moving to a custom domain, follow [Move to your own domain](docs/i18n-seo.md#move-to-your-own-domain).

## Tests

End-to-end tests in `tests/e2e/` run with Playwright in the installed Google Chrome, on a desktop and a mobile viewport. By default they test a separate local production build; `E2E_BASE_URL` points them at a deployed site instead. External services are always mocked.

```bash
npm run test:e2e
E2E_BASE_URL=https://luca2409.github.io/schwarz-amp-industrial/ npm run test:e2e
```

Test list, debugging and how to write a test: [docs/quality-checks.md](docs/quality-checks.md#end-to-end-tests).

## Styling

All styles are in `src/styles/global.css`, which is imported once by `BaseLayout.astro`. Components don't use scoped `<style>` blocks.

### Design tokens

Colors, spacing and sizes are CSS custom properties on `:root`, e.g. `--yellow` (accent), `--black`, `--off` (light background), `--error` (error messages), `--content-max` (1440px), `--page-padding`. Use them instead of hard-coded values.

### Class naming

- **Reusable:** `.button` (+ `--primary`, `--secondary`, `--accent`), `.eyebrow` (+ `--dark`), `.section-heading`, `.markdown-content`
- **Component-specific:** BEM-style per component, e.g. `.site-header`, `.main-navigation__link`, `.hero__copy`, `.hero__visual`, `.competency-row__title`, `.quality-card`, `.contact-banner`

New components should use the reusable classes first and add their own classes only for component-specific layout.

### File layout

`global.css` is organized in commented sections: reusable, header, hero, image showcase, about, competencies, quality, contact (banner), footer, detail pages, contact page, industrial detailing, responsive. Breakpoints are 1050px, 1040px (main navigation switches to the menu button), 900px and 560px. Most media queries are in the responsive section at the end; the image showcase and the contact page keep theirs next to their styles. A `prefers-reduced-motion` query turns off smooth scrolling and transitions.

### Header logo

The header logo is plain HTML/CSS (`.brand__name`, `.brand__line`, `.brand__subtitle` in `Header.astro`), not an image, so it stays sharp at every resolution and its subtitle is translated. `public/images/logo-amp.png` is only used for structured data.

### Design direction

"Industrial" style: sharp corners, strong separators, technical typography, uppercase navigation labels, reduced shadows, subtle grid details, flat competency rows, square action arrows, disciplined spacing, yellow as the only accent color.
